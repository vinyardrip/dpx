Универсальный CLI для управления DDEV-проектами. DPX дополняет DDEV операциями с базами данных (обновление с продакшена, снимки, восстановление), созданием проектов для шести CMS и фреймворков, публичными туннелями через Cloudflare и ngrok с автоматическим откатом, переключением версий PHP, метаданными проектов и самообновлением.

---

**Проект активно развивается.** Стабильные команды: `list`, `set-php`, `edit`, `ddev`, `tunnel`, `db-snap`, `db-restore`, `to-prod`, `backup`, `new`, `config`. Команды `migrate`, `deploy`, `refresh` требуют дополнительного полевого тестирования в разных окружениях. Отчёты об ошибках и обратная связь приветствуются.

## Целостность данных

DPX следует политике **Zero-Trust** при работе с данными: ни одна мутация — замена URL, переключение PHP, импорт дампа или изменение конфигурации — не начинается без подготовленного пути отката. Перед разрушительными операциями с БД создаются снимки (`ddev snapshot`), изменение `wp-config.php` проходит цикл резервная копия → патч → `php -l` → проверка → откат, а изменения `/etc/hosts` выполняются через Safe-Sudo Protocol: резервная копия → правка → проверка → откат. Прерывание операции через Ctrl+C запускает зарегистрированные cleanup-trap-обработчики: `wp-config.php` восстанавливается побайтово, URL возвращаются к исходным значениям, процесс туннеля и временные файлы удаляются.

## Требования

| Зависимость               | Мин. версия | Примечание                                        |
| ------------------------- | :---------: | ------------------------------------------------- |
| **Bash**                  |  **4.4+**   | Ассоциативные массивы, `read -ra`, `mapfile`      |
| DDEV                      |   1.21.0+   | Локальное окружение разработки                    |
| Docker                    |   20.10+    | Контейнерный движок; daemon должен быть запущен   |
| jq                        |    1.5+     | Парсинг JSON от `ddev describe` и API ngrok       |
| sed, grep, awk, curl, tar |      —      | Стандартные утилиты GNU/BSD                       |

### Примечание для macOS

В macOS предустановлен Bash 3.2, который **не поддерживается** из-за отсутствия ассоциативных массивов. Установите современный Bash через Homebrew и убедитесь, что он находится в `PATH` раньше `/bin/bash`. BSD-специфичная логика — BSD `sed -i ''`, `stat -f`, `readlink` без `-f`, порядок параметров bsdtar — покрыта автоматическим набором симуляционных тестов и не требует ручной адаптации.

## Установка

```bash
git clone https://github.com/vinyardrip/dpx.git
cd dpx
./install.sh            # симлинк в ~/.local/bin, sudo не требуется
```

Глобальная установка: `sudo ./install.sh install-global`. Только проверка зависимостей: `./install.sh check`.
Обновление: `dpx update` (git fetch + pull + повторная установка симлинка). Удаление: `./install.sh uninstall`.

## Быстрый старт

```bash
dpx                     # при первом запуске откроется мастер настройки
dpx list                # показать все DDEV-проекты
dpx new                 # создать проект с интерактивным выбором типа
dpx tunnel              # открыть публичный доступ к запущенному проекту
dpx refresh             # обновить локальную БД из продакшен-дампа
dpx backup              # полный бэкап проекта: файлы + база данных
dpx config --show       # показать активную конфигурацию
```

## Матрица команд

| Команда | Назначение | Основные возможности |
| ------- | ---------- | -------------------- |
| `dpx new` | Создание нового проекта | 6 типов: WordPress, Joomla, OpenCart, ocStore, Laravel, Plain PHP; флаги `--cms=`, `--php=`, `--db`, `-y`; имя можно передать позиционно |
| `dpx new-wp` | Алиас для обратной совместимости | Эквивалент `dpx new --cms=wordpress`; WordPress-флаги передаются дальше |
| `dpx tunnel` | Публичный URL для запущенного проекта | Провайдеры `cloudflare` и `ngrok`; smart-блок в `wp-config.php`; Nginx override; Ctrl+C запускает полный откат |
| `dpx migrate` | Миграция проекта из Devilbox в DDEV | Перенос БД, сопоставление версии PHP |
| `dpx deploy` | Развёртывание существующего проекта в DDEV | Импорт продакшен-дампа, выбор типа CMS |
| `dpx db pull` / `refresh` | Обновление локальной БД с продакшена | Замена URL через WP-CLI или SQL, мягкий перезапуск контейнеров перед импортом |
| `dpx db snap` / `db-snap` | Быстрый локальный снимок БД | Ротация: сохраняются последние 3 снимка |
| `dpx db restore` / `db-restore` | Восстановление БД из локального бэкапа | Защитный дамп перед импортом, постобработка с учётом CMS |
| `dpx db push` / `to-prod` | Подготовка локальной БД к выгрузке на продакшен | Обратная замена URL, ротация дампов |
| `dpx site backup` / `backup` | Полный бэкап проекта: файлы + БД | `FULL_<name>_<timestamp>.tar.gz`, исключение тяжёлых каталогов, настраиваемая ротация |
| `dpx site restore` / `restore` | Восстановление полного архива | Защитный снимок БД → распаковка кода и uploads → импорт встроенного дампа → очистка кэша CMS |
| `dpx site new` / `new` | Создание проекта, аналог `dpx new` | 6 типов проектов |
| `dpx site migrate` / `migrate` | Миграция из Devilbox | |
| `dpx site deploy` / `deploy` | Развёртывание кодовой базы в DDEV | |
| `dpx config` | Интерактивный мастер настройки и `--show` | Записывает `~/.config/dpx/dpx.conf` |
| `dpx ddev` | Выполнение любой команды DDEV для выбранного проекта | Работает вне каталогов проектов |
| `dpx list` | Список проектов | Сортировка по PHP и статусу, JSON, группировка |
| `dpx set-php` | Смена версии PHP проекта | Перед изменением автоматически создаётся бэкап БД |
| `dpx edit` | Метаданные проекта: `php_max`, заметки | Хранятся в `~/.config/dpx/projects.json` |
| `dpx info` | Отчёт об окружении и конфигурации | Статусы зависимостей с цветовой индикацией |
| `dpx update` | Самообновление из Git | Перед установкой показывает входящие коммиты |

## Обзор архитектуры

```
dpx.sh                  Точка входа и роутер: source нужной команды после bash -n
commands/*.sh           Тонкий слой команд: разбор аргументов и оркестрация
lib/
├── core.sh             Загрузчик модулей; подключает цепочку ниже по порядку
├── paths.sh            Определение ОС linux/macos и пути DPX_ROOT
├── i18n.sh             Цепочка локали DPX_LANG → LC_ALL → LANG → en; функция t()
├── io.sh               Функции print_* для STDERR и управление цветом
├── config.sh           Каскадная конфигурация: system → user → project
├── args.sh             Парсинг CLI, включая формат --key=value
├── checks.sh           Проверки зависимостей, версий и окружения
├── sudo.sh             Safe-Sudo Protocol для привилегированных правок
├── cms.sh              Реестр CMS, интерактивный выбор, обработчики очистки кэша
├── projects.sh         Поиск и выбор проектов
├── ddev.sh             Обёртки DDEV: start, restart, import-db, export-db и другие
├── database.sh         Импорт и экспорт дампов, определение имени БД, снимки
├── backup.sh           Полные бэкапы проекта с ротацией
├── devilbox.sh         Интеграция с Devilbox для миграции
├── meta.sh             Метаданные projects.json
└── utils.sh            safe_sed_inplace, prompts и функции валидации
tests/test_*.sh         Модульные и e2e-наборы; см. раздел «Тестирование»
```

Основные правила:

- Каждый модуль защищён от повторного подключения; порядок загрузки учитывает зависимости.
- **STDOUT предназначен для данных, STDERR — для интерфейса.** Функции, возвращающие значения, например `project_full_backup`, не смешивают результат с диалоговыми сообщениями.
- Роутер подключает команды по одной и перед выполнением проверяет их синтаксис через `bash -n`.

## Конфигурация

Основной файл настроек — `~/.config/dpx/dpx.conf`, формат INI-подобный: `key = value`. Проектный файл `config/dpx.conf` может переопределять отдельные параметры; системный `/etc/dpx/dpx.conf`, если он существует, загружается первым.

```ini
ddev_projects_base_path = ~/projects/php
default_tunnel_provider = ngrok        # ngrok | cloudflare
db_user = db                           # учётные данные MySQL/MariaDB для scaffold-команд
db_password = db
cli_lang = auto                        # auto | en | ru — язык CLI
default_php_version = 8.1
project_tld = lo
full_backup_path = ~/projects/backups
full_backup_keep = 3
auto_update_check = true               # ежедневная неблокирующая проверка обновлений
```

Настройками можно управлять без ручного редактирования файла:

```bash
dpx config            # интерактивный мастер: каталог проектов, провайдер туннеля,
                      # учётные данные БД и язык CLI
dpx config --show     # активные значения и путь к файлу конфигурации
dpx config --projects-root ~/work/php --provider cloudflare --lang ru -y
```

**Первый запуск:** если `~/.config/dpx/dpx.conf` отсутствует, первый вызов `dpx` автоматически запускает мастер настройки в интерактивном терминале. В неинтерактивной сессии DPX не зависает, а выводит подсказку с командой `dpx config`.

## Туннели

`dpx tunnel` публикует запущенный проект через Cloudflare Tunnel или ngrok. Для WordPress команда выполняет три согласованных действия: заменяет URL в БД, добавляет в `wp-config.php` блок `DPX_SMART_TUNNEL` с условным HTTPS через `X-Forwarded-Proto` и корректным Host, а также подключает Nginx override с `absolute_redirect off`, `port_in_redirect off` и proxy-заголовками. Затем регистрируются cleanup-trap-обработчики, поэтому Ctrl+C полностью восстанавливает исходное состояние. Драйвер ngrok получает публичный HTTPS URL из локального API `127.0.0.1:4040/api/tunnels`, используя цепочку парсеров jq → python3 → grep.

## Тестирование и контроль качества

```bash
./run_tests.sh                    # ShellCheck gate + все наборы, профиль Linux
bash tests/test_macos_sim.sh      # отдельный прогон симуляции macOS/BSD
```

Текущее состояние: **229 тестов**, из них 225 проходят и 4 пропускаются при отсутствии PHP CLI на хосте. Проверяются два платформенных профиля: нативный Linux и симуляция Darwin с BSD-shim-реализациями для `sed`, `stat`, `readlink` и `tar`. В раннер встроен ShellCheck gate: любая найденная проблема останавливает сборку. Наборы покрывают ядро, тестовый фреймворк, macOS/BSD, универсальный scaffold `new`, туннельные патчи и ngrok, мастер конфигурации, i18n и очистку временных файлов.
